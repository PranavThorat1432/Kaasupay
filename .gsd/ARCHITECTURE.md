# Architecture

> Generated by /map on 2026-10-29

## Overview

KaasuPay is a full-stack, fintech digital-wallet application built on Node.js/Express, MongoDB (Replica Set), React 19, Redux Toolkit, and Vite. The system is architected around financial accuracy, double-entry ledger immutability, cryptographic idempotency, transactional outbox payout processing, and multi-layered defense-in-depth security.

## Data Flow

### 1. Peer-to-Peer Transfer Flow
1. **Frontend Initiation**: User enters recipient, amount, note, and submits.
2. **Security Gate**: If user has a PIN, `PinModal` collects PIN.
3. **API Request**: `POST /api/v1/wallet/transfer` with `Bearer JWT`, `Idempotency-Key`, and `{ to, amount, note, pin }`.
4. **Middleware Validation**:
   - `rateLimiter`: Enforces 10 money operations / min.
   - `requireAuth`: Verifies JWT signature and `tokenVersion`.
5. **Controller Processing**:
   - Validates input bounds (₹1.00 to ₹10,000.00).
   - Verifies PIN via `verifyPin`: atomic check; on 3 failures locks for 15m (`423`).
   - Inserts `IdempotencyRecord` in `IN_PROGRESS` state. On duplicate `E11000`: replays if `DONE` or returns `409` if `IN_PROGRESS`.
6. **Transactional Execution (`services/money.js`)**:
   - Inside MongoDB replica set transaction session:
     - `checkAndConsumeDailyLimit`: Atomically reserves spend against ₹10,000/day limit.
     - `Wallet.findOneAndUpdate`: Atomically debits sender (`balance >= amount`).
     - `Wallet.findOneAndUpdate`: Atomically credits receiver.
     - `Transaction.create`: Creates `TRANSFER` document (`status: "COMPLETED"`).
     - `LedgerEntry.insertMany`: Creates 1 `DEBIT` entry for sender and 1 `CREDIT` entry for receiver with `balanceAfter`.
7. **Idempotency Finalization**: Updates `IdempotencyRecord` to `DONE` with HTTP 201 response payload.
8. **Frontend Response**: Displays transfer confirmation receipt and refreshes Redux balance and transaction list.

### 2. Bank Withdrawal & Outbox Payout Flow
1. **Frontend Initiation**: User selects masked bank account, enters amount, and enters PIN.
2. **API Request**: `POST /api/v1/wallet/withdraw` with `Idempotency-Key` and `{ bankAccountId, amount, pin }`.
3. **Immediate Reservation**:
   - PIN verified and daily limit checked.
   - Wallet balance atomically debited immediately.
   - `Withdrawal` created in `PENDING` state.
   - `OutboxEvent` created in `NEW` state.
   - Returns `HTTP 202 Accepted` with withdrawal ID.
4. **Asynchronous Worker (`worker.js`)**:
   - `claimNextJob`: Claims job atomically (`status: "NEW"`, `lockedAt: now`).
   - Decrypts account number using AES-256-GCM.
   - Calls Partner Bank API with 3000ms timeout using stable idempotency reference `wd_<withdrawalId>`.
   - **On Success**: `Withdrawal` updated to `SUCCESS` with bank UTR; `OutboxEvent` updated to `DONE`.
   - **On Closed Account**: `Withdrawal` updated to `REVERSED`; compensating refund credited to wallet with `REVERSAL` transaction and `CREDIT` ledger entry; `OutboxEvent` updated to `DONE`.
   - **On Bank Unavailable / Timeout**: Job rescheduled with exponential backoff. After 5 attempts, transitioned to `NEEDS_REVIEW` (stuck state, balance held safely).
5. **Staff Resolution**: Staff can inspect bank status (`GET /api/v1/admin/withdrawals/:id/bank-status`) and execute idempotent refund (`POST /api/v1/admin/withdrawals/:id/resolve`).

## Conventions

- **Naming:**
  - Files: camelCase for JavaScript utilities and backend controllers (`walletController.js`); PascalCase for React components (`DashboardPage.jsx`).
  - Currency: Stored internally as integer paise (`amount`, `balance`); formatted with `₹` and 2 decimal places for user display. Never use floating-point math for money.
- **Error Handling:**
  - Standard JSON response `{ error: string }` or `{ message: string }`.
  - Specific HTTP statuses: `400` validation/insufficient funds, `401` unauthorized/bad session, `403` wrong PIN, `404` not found, `409` in-progress duplicate/conflict, `422` idempotency payload mismatch, `423` PIN locked, `429` rate limited, `502` upstream bank/gateway error.
- **Testing:**
  - Standalone Node.js test runners using in-memory MongoDB replica sets (`mongodb-memory-server`) and mock HTTP servers.
  - Assertions tracked via deterministic assertion counters (`check()` function).

## Technical Debt & Identified Risks

- [ ] **Mongoose Deprecation Warnings**: In `findOneAndUpdate()` and `findOneAndReplace()`, `{ new: true }` is deprecated in Mongoose 9.x; replace with `{ returnDocument: 'after' }` across older controllers.
- [ ] **Hardcoded Daily Limit**: `DAILY_LIMIT_PAISE = 1000000` is currently a module constant in `dailyLimitService.js`; should be configurable via environment variable or tiered user roles.
- [ ] **Daily Limit on Withdrawal Reversals**: Reversals currently do not restore spent daily limits; by design per Day 6 specification, but should be documented clearly in user-facing FAQs.
- [ ] **Admin Authentication**: `ADMIN_KEY` header verification is a single shared secret without granular role-based permissions or audit trails.
- [ ] **Worker Scaling**: Worker lease uses polling with `sleep(1000)`; under high volume, change streams or Redis queue would reduce database polling load.
